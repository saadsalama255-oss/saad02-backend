# FrozenGuard Cloud Migration Starter

## ما الذي يحتويه هذا الإصدار؟
- `frontend/index-light-green.html`: نسخة واجهة بتدرجات أخضر فاتح وتباين أوضح.
- `backend/`: خدمة Node.js + Express + PostgreSQL + Socket.IO، مع JWT وتخزين سجلات مركزي.
- **هذا ليس ترحيلًا مكتملًا للتطبيق الحالي.** الواجهة الحالية ما زالت تحتوي على منطق `localStorage` و`db` المحلي، ولم يتم توصيل جميع النماذج والتقارير والصلاحيات في هذه الحزمة إلى API. لا تنشرها باعتبارها نسخة مركزية مكتملة قبل إنهاء ربط الواجهة واختبار ترحيل البيانات.

## إعداد Render
1. أنشئ PostgreSQL من لوحة Render، واحتفظ بـ Internal Database URL عند تشغيل الـ API على Render.
2. ارفع مجلد `backend` إلى مستودع GitHub.
3. أنشئ Web Service من المستودع، واجعل Root Directory = `backend`، Build Command = `npm install`، Start Command = `npm start`.
4. أضف متغيرات البيئة:
   - `DATABASE_URL`: رابط قاعدة البيانات الداخلي من Render.
   - `JWT_SECRET`: قيمة عشوائية طويلة وفريدة (لا تضعها في كود الواجهة).
   - `FRONTEND_ORIGIN`: أصل موقع الواجهة، مثل `https://example.onrender.com` أو رابط GitHub Pages.
5. بعد نشر الـ API، افتح `/health` وتأكد من ظهور `{"ok":true,...}`.
6. أنشئ أول مدير بطريقة آمنة من Render Shell بعد تثبيت الاعتمادات وضبط المتغيرات:
   `node create-admin.js admin "مدير النظام" "USE-A-UNIQUE-PASSWORD-AT-LEAST-12-CHARS"`
   استبدل كلمة المرور بمفتاح قوي وفريد، ولا تستخدم المثال حرفيًا.
7. استدعاء تسجيل الدخول يكون `POST /api/auth/login` بجسم JSON يحتوي `username` و`password`. استخدم رمز JWT في `Authorization: Bearer <token>`.

## API الحالي
- `GET /api/collections/:collection` — قراءة سجلات القسم.
- `PUT /api/collections/:collection/:id` — إضافة/استبدال سجل.
- `DELETE /api/collections/:collection/:id` — حذف سجل.
- WebSocket عبر Socket.IO: اتصل مع `auth: { token }` ثم أرسل `subscribe` باسم القسم؛ تصل أحداث `record:changed`.

## ملاحظة مهمة عن المزامنة
الخادم يبث الحدث بعد نجاح الكتابة في PostgreSQL، لذلك يتلقى المشتركون إشعارًا بالتغيير. على الواجهة تطبيق الحدث على الحالة المعروضة أو إعادة جلب القسم. هذه الآلية لا تدمج التعديلات المتزامنة تلقائيًا ولا تحل تعارضات السجلات؛ يلزم إضافة سياسة تعارض/إصدارات واختبار صلاحيات كل قسم قبل الاستخدام الفعلي.

## قبل نقل البيانات
- صدّر نسخة احتياطية كاملة من التطبيق الحالي واحفظها خارج الموقع.
- جرّب الترحيل على نسخة تجريبية أولًا، وتحقق من أعداد السجلات في جميع الأقسام، بما فيها `rcv`, `batches`, `ops`, `mvs`, `users`, `set` والحقول المتداخلة.
- لا تحذف البيانات المحلية حتى يتم التحقق من تطابق البيانات والتقارير.
- كلمات المرور القديمة مخزنة بصيغة hash ضعيفة داخل الكود الحالي؛ لا تنقلها كما هي. استخدم إعادة تعيين كلمات المرور وتخزين bcrypt في الخادم.
